# Codemap

- `tools/z3dmods/cli.py`: the `z3dmods` commands; composes the modules below.
- `tools/z3dmods/config.py`: the one reader of the environment and the local settings: a checkout's `env-assets/local.json`, or a package's layout and the player's `folders.json`.
- `shared/setup-ui` (beside this repo's parent, consumed by `app/CMakeLists.txt` like Lucent): the first-run screen every port shows; RmlUi from the `RmlUi` checkout beside it.
- `tools/z3dmods/ctr.py`: decrypted CCI/NCCH/exheader/ExeFS/RomFS reading and `.code` LZ decompression.
- `tools/z3dmods/zsi.py`: OoT3D and MM3D room files: header commands, their CMB models, replacing a model and moving what follows. Scene files: the collision's vertices and triangles, read and written.
- `tools/z3dmods/cmb.py`: CMB models, OoT3D's version 6 and MM3D's 10: textures, materials, meshes, vertices; rewriting one shape's geometry.
- `tools/z3dmods/lzs.py`: unpacks MM3D's LzS-wrapped game files.
- `tools/z3dmods/etc1.py`: 3DS ETC1/ETC1A4 texture decoding.
- `tools/z3dmods/pica_texture.py`: PICA texture decoding (RGBA4444, 4-bit alpha, ETC1, ETC1A4), 4-bit alpha encoding and Azahar's custom-texture file name, by either of its hashes.
- `tools/z3dmods/cityhash.py`: CityHash64, the hash under Azahar's texture names.
- `tools/z3dmods/source_check.py`: a set's third-party files found among the player's mod downloads by the set's hashes (archives unpacked first), and the refusal that names a missing or different one and where to get it.
- `tools/z3dmods/texture_pack.py`: finds a game texture's replacement in an Azahar texture pack by the hash its `pack.json` names.
- `tools/z3dmods/ctxb.py`: CTXB menu texture bundles.
- `tools/z3dmods/gar.py`: GAR v2 archives (MM3D's layout bundles).
- `tools/z3dmods/hud.py`: redoes a base mod's menu-texture edits on the texture pack's high-resolution copies and draws port-assets' pad glyphs over the 3DS button prompts (edit tables in `sets/hud/`), and the text's prompt sheet again with the app's key caps for the pack's keyboard variant.
- `tools/z3dmods/hud_icons.py`: the game art the app's play HUD draws, cut from the game's sheets or the pack's copies: item icons by the game's icon table, named pieces and the A button's words (`[icons]`, `[art]`, `[words]` in `patch/<game>/hud.toml`).
- `tools/z3dmods/text.py`: a game's own text for the PC, from its table in `sets/text/`: the text font drawn from an outline font (`sets/fonts/`) into the game's font file and the pack's images, and the messages' prompt words reworded.
- `tools/z3dmods/text_font.py`: an outline font fitted to a bitmap font's cells (capital height, baseline, tracking) and drawn into them at the game's size and a pack's scale.
- `tools/z3dmods/qbf.py`: OoT3D's QBF1 font, read and written, and the static glyph texture the game makes of it.
- `tools/z3dmods/gzf.py`: MM3D's GZFX font, read and written.
- `tools/z3dmods/qm.py`: OoT3D's QM message file, read and written, and a message's text as markup.
- `tools/z3dmods/gmsg.py`: MM3D's GMSG message file, read and written, and a message's text as markup.
- `tools/z3dmods/stairs.py`: folds stair-textured ramps in a game's rooms into risers and treads, and the scene's collision triangles on them the same way.
- `tools/z3dmods/bgcheck.py`: the room a scene's collision has in the game: the grid and memory `BgCheck_Allocate` gives a scene (its tables read from the code at the decomp's addresses), the list nodes the triangles take, and the limits `install` refuses a stepped scene over.
- `tools/z3dmods/ips.py`: IPS parse, apply and build.
- `tools/z3dmods/bps.py`: BPS info and apply, with source and target CRC checks.
- `tools/z3dmods/install.py`: installs a `sets/<game>.json` set into Azahar's `load/`, with an install record.
- `tools/z3dmods/azahar_config.py`: global `qt-config.ini` edits.
- `tools/z3dmods/azahar.py`: the headless Azahar session (Gamescope, XTest keys, RPC RAM and frames, config restore).
- `tools/z3dmods/steps.py`: the scripted step language for runs, over either backend.
- `tools/z3dmods/app.py`: the z3d app's build: the pinned Azahar fork's core into a per-revision prefix, then the app against it; its user folders (copies of the player's data, a link to `load/`) and its flags for a set.
- `tools/z3dmods/harness.py`: the app headless as the run backend: frame-exact input, savestates, watchpoints.
- `tools/z3dmods/input_test.py`: `z3dmods inputtest`: the windowed app in a headless Gamescope driven by XTest keys and mouse and a uinput pad; the picker scenario runs the installed shortcut.
- `tools/z3dmods/app_keys.py`: the app's key and mouse bindings read from `z3d --keys`, as X keysyms for the input tests.
- `tools/z3dmods/play.py`: `z3dmods play [game]`: the app in a window on the player's session, with its own saves: the title picker over the library it writes, or one game.
- `tools/z3dmods/shortcut.py`: the per-machine desktop shortcut that runs `z3dmods play`.
- `tools/z3dmods/setup.py`: `z3dmods setup --user <folder> <dump>`: the set of a dump's game installed into an app user folder; the app's picker runs it. How a refusal is printed for the app.
- `tools/z3dmods/set_inputs.py`: the digest of what of ours a set is made from (set, tables, patch, glyphs, tools), which the install writes into the options manifest and a package's library names.
- `tools/z3dmods/glyphs.py`: port-assets' pad glyphs drawn large by ImageMagick, once per checkout or into a package (`prebuilt/glyphs/`), for the menu textures.
- `tools/z3dmods/build_container.py`: the podman image the package's app and core are built in (`packaging/Containerfile`), which sets the oldest glibc and libstdc++ a desktop needs.
- `tools/z3dmods/desktop_container.py`: a container of the oldest distribution the package runs on (`packaging/Containerfile.desktop`), where the input test starts the AppImage.
- `tools/z3dmods/host_install.py`: `z3dmods shortcut --host`: the package in another machine's `~/Games/z3d`, the player's data there kept and copied aside, with its shortcuts.
- `tools/z3dmods/package.py`: `z3dmods package`: the Linux package folder (an AppDir): app, every library it links but the C and C++ runtimes, a relocatable Python with the locked wheels, the tools, sets, prebuilt patches and glyphs, assets, the source's commits (`SOURCE.txt`) and the licences of what is not ours (`licenses/`); and the AppImage of that folder. Refuses a package that needs a newer glibc than the container's or names this machine's folders.
- `tools/z3dmods/sources.py`: the checkouts the app is built from besides this one (the core, Lucent, setup-ui, RmlUi, port-assets) and the AppImage runtime: where each lives, the revision `z3dmods sources` fetches where one is missing, and the commit a build names as its source.
- `.github/workflows/release.yml`: the hosted build of the package, by hand or from a release tag (plans/packed-app.md, "The release"); `packaging/Containerfile.glyphs` is its ImageMagick.
- `docs/releases/<tag>.md`: a release's notes.
- `tools/z3dmods/packed.py`: the package's entry point (`python -m z3dmods.packed`): `play` over the player's dump folder, and what the picker runs: `folders` (takes a folder the player chose, keeps it in `folders.json`, writes the library) and `setup`.
- `tools/z3dmods/symbols.py`: reads each game's decomp (function maps, header offsets, globals) and generates a patch's guest constants; in a package, reads the table saved from it (`prebuilt/<game>/symbols.json`).
- `tools/z3dmods/games.py`: per-game guest RAM layout the run steps read (play state, save context, cutscene), resolved from the decomp.
- `tools/z3dmods/patch_build.py`: builds our MIT patch (`patch/<game>/`) into IPS records with clang and lld; saves a build for a package and reads it back there (`prebuilt/<game>/code.ips`, `hooks.json`).
- `tools/z3dmods/options.py`: a patch's switches (`patch/<game>/options.toml`): the generated `options.hpp` and the manifest the app's options menu reads.
- `tools/z3dmods/slot_link.py`: the item slots' block a patch shares with the app: the generated `slot_link.hpp` and its addresses in the manifest.
- `decomp/oot3d/`: submodule, our fork of zeldaret/oot3d (CC0): OoT3D symbols, structs and RE docs.
- `decomp/mm3d/`: submodule, SomeoneIsWorking/mm3d-decomp (MIT): MM3D 1.0-layout symbols, structs and RE docs.
- `patch/<game>/symbols.toml`: which decomp functions, globals and offsets a patch uses.
- `patch/common/`: guest memory and call helpers for the patches, the Start cutscene skip shared by both games, and the mouse's camera turn taken from the link block (`mouse_look.hpp`).
  - `slots.hpp`: the item slots both games' patches share: slot values packed for a save's spare bytes, and which of the game's item buttons carry the slots in use.
  - `song_sequence.hpp`: a song's notes held one after another in the pad for the game to recognise.
  - `ctr.hpp`: 3DS kernel calls and service IPC from inside a title.
  - `cstick.hpp`: the New 3DS C-stick, read from `ir:rst`'s shared memory.
- `patch/oot3d/`: our OoT3D patch: guest layout (`game.hpp`), the Start cutscene skip, its script reader (`cutscene_script.hpp`), Quick Text (`quick_text.cpp`), the text font as one fixed texture (`font_atlas.cpp`), the right-stick and mouse free camera (`free_camera.cpp`), the item slots (`slot_items.cpp`) and a slot's song played on the ocarina (`song_player.cpp`), autosave (`autosave.cpp`), the per-frame hook that runs them (`play_update.cpp`), its switches (`options.toml`), hook sites and link script.
- `patch/mm3d/`: our MM3D patch on Project Restoration's code layout: guest layout (`game.hpp`), the skip's layout, its script reader (`cutscene_script.hpp`), Quick Text (`quick_text.cpp`), autosave (`autosave.cpp`), the per-frame update in front of Play_Update and its plain-play test (`play_update.cpp`), View again on the Map screen opening the Bombers' Notebook (`notebook.cpp`), the item slots with their songs (`slot_items.cpp`), the game's own A button hidden (`base_hud.cpp`), the mouse turning the game's C-stick camera (`mouse_camera.cpp`), its switches (`options.toml`), hook sites and link script.
- `app/`: `z3d`, a frontend linked to Azahar's core (the fork's installed `AzaharCore` package): a window to play in, or hidden and driven by stdin lines.
  - `app_config`: the typed command line; a game's setup (ROM, layout, textures).
  - `core_settings`: the core's settings and user path from the config, applied first; a game's settings before it loads.
  - `core_log`: the core's log backend for the app's lifetime.
  - `game_library`: the picker's games from the tools' library file, titles and icons from each dump's SMDH.
  - `game_options`: a game's options: the patch's switches from its manifest plus layout and textures, the player's stored choices, the write into the guest block.
  - `screen_overlay`: the overlay layout: pieces of the touch screen drawn on the top screen from the game's table of layouts (`patch/<game>/overlay.toml`) by which touch screen is up, and the mouse mapped back through them.
  - `hud`: the play HUD for every game: element kinds (hearts, meter, counter, button, prompt, panel) read from guest memory and the item slots by the game's table (`patch/<game>/hud.toml`) and drawn as quads of the atlas.
  - `hud_atlas`: port-assets SVGs, lettering and item icons rasterized at the window's size into the image the core draws.
  - `prompt_art`: the port-assets set and file of each pad glyph, key cap and mouse button a prompt draws, and their loader.
  - `tool_process`: one run of the tools as a child process: its printed lines and its refusal.
  - `set_install`: whether a game's set in the user folder is the one the tools make now (missing, or made from other inputs), and the tools' setup run on the player's dump when it is not.
  - `menu_canvas`: the SDL renderer and outline font the picker and its screens draw with between games, and their hint lines (pad glyphs or key caps by the last device).
  - `folder_setup`: the first run's questions (dump folder, mods folder) on the shared setup screen (`shared/setup-ui`), answered in the folder browser and taken by the tools.
  - `folder_browser`: the in-window folder chooser, by pad, keys or mouse.
  - `mod_swap`: the running game's patch put in, taken out or read again from disk, and its texture pack turned on and off.
  - `options_menu`: the picker's options screen for one game.
  - `title_picker`: the in-window title picker (SDL3_ttf outline text on the menu canvas), pad and click.
  - `game_window`: the SDL3 window as the core's `EmuWindow`: native Vulkan surface, per-frame event pump, mouse touch, the menu request; the picker's pump.
  - `pad_input`: the core's `z3d` input engine: the pad, keyboard and mouse tables (verbs and item slots in play, 3DS buttons by name elsewhere) and tool commands; the menus' pad (`MenuPad`), read by the host's button names.
  - `term_signal`: SIGTERM and SIGINT: SDL's quit event for the window's loop, and the process ended when the loop cannot take it.
  - `slot_link`: the item slots' block in the running game's patch: the held slots written in, the pad table the game wants and each slot's content read out.
  - `mouse_aim`: the mouse as the 3DS's gyroscope while the game's first-person look follows it (`patch/<game>/aim.toml`), and as the camera's turn through the link block in the rest of play.
  - `emulator`: game load, frame stepping, guest memory, savestates, screenshots and write watches.
  - `player`: the windowed loop, paced by the core's frame limiter, until close or the menu request.
  - `frame`: a captured frame and its PNG encoding.
  - `repl`: the stdin command language.
  - `icon/z3d.svg`: the app's icon.
- `sets/`: per-game mod set manifests.
